## 问题、最小建议与依赖

### 当前无通关阻塞

本轮没有确认需要立即修改运行时的 P0 故障。两次掉落都能按现有规则恢复，最后完成通关；不要据此擅自降低摆锤力度、增大摩擦或调整控制参数。

### 进度显示的已知限制

重现：通过检查点一后，沿横桥向右移动但 Z 基本不变，进度基本停留在约 0.64；直到触发检查点二才前进。最终向右驶向终点时，Z 基本不变，进度约 0.96，完赛时跳至 1。实际读数见 `narrow-bridge-exit`、`checkpoint-two-approach-before-brake`、`first-full-route-finish-before-brake`。

原因：当前进度只使用 Z 与已通过检查点数量，不计算 X 或轨迹长度。当前仍可通关。最小建议是本轮提案继续沿现有格式调整分段参数并说明限制；如果产品要求横向路段也连续增长，则需单独分派代码任务扩展分段轴或路线进度算法，不能由关卡对话直接修改运行时。

### 正式改变布局前的成绩兼容门槛

重现/依据：`src/state.ts` 的 `Run` 只有 `time/falls/date`，统一保存在 `marble-lab-v1`，没有关卡 ID 或布局版本。换布局后旧成绩仍会参与“个人最佳”与排序。

最小建议：若统筹选择会影响用时比较的布局改动，先分派代码任务制定并实现成绩版本兼容，保留旧成绩，明确旧纪录展示和新纪录比较范围；不要删存储或直接混用。纯外观修改且碰撞、路线不变通常不需要成绩迁移。

### 整关模型与配置必须配套交付

重现/依据：当前 GLB 包含整关坐标，生成脚本不读取 TypeScript 配置；只改 `staticObjects` 不会让精细模型跟随变化。

最小建议：后续布局实施按“成绩兼容就绪 → 关卡基础几何版本并冻结配置 → 美术按冻结配置制作 → 关卡更新引用 → 代码验证”流转。调布局期间关闭精细模型，按配置 SHA-256 交付匹配资源；本轮没有关闭模型或重做资源。

### 包体积与视觉判断

构建大包警告未阻塞本地加载，本轮未做加载体积优化；正式发布前另行评估。实际截图中浅色轨道、浅色背景与提示标识的可辨性由 ART-01 与 LEVEL-01 结合用户反馈提出方案，本报告不把单次工具试玩转化为“太难/太单调”的产品结论。
