# 顶级难度关卡与第四关 · 正式开发

2026-09-14。用户明确要求让三个执行任务继续工作，将已经完成设计的两条赛道开发接入。本文件把两条设计转为实施范围，覆盖此前相关文件“仅设计/不派实现”的阶段限制。复杂新八机关仍只是独立设计，本轮不混入。

## 两项产品交付

1. `top-difficulty` / **顶级难度关卡**：依据原387.253米、10连续段、36机关单元、13类每种至少两次的单路线设计。保留该设计的连续短接头与4边界CP，不能改成三路。以设计为基线，真实接缝/相位经技术验证需修订时由LEVEL更新并交ART对应，不把候选数值当必须硬保留的已验证结果。
2. `three-route` / **三路分流**：正式第四关。起点单锤→推墙两个机关，十字分流另计，A/B/C任选一条，真实Y形汇合，公共蛇形→惯性坡两个机关后到终点。整图37单元，各路线约255–264米；路线长度以最终实现重新核对。分支不要求全走，所有三路均需实际可进入、完成、汇合与结算。

保留现有教学/水上冲关/机关试炼，不以新布局覆盖现有id或成绩。目录中three-route编号04；top-difficulty为独立命名挑战，编号槽用中文“挑战”，不把它误标第三关或挤占第四关，当前共有五个可选内容。两个新id首版rulesVersion均可用现成standard，按id+规则独立保存；不套旧奖牌阈值，不清空用户设置和所有旧桶。

## CODE · 共用能力先行

- 首先交 `docs/integration/course-authoring-contract.md`，定义旧机关的多实例/局部朝向/相位、组id、静态路段与资源引用、端口/CP/分支进度字段及数据边界。同时实现对应能力，再通知LEVEL转正式TS。协议与实现就绪分开报告，不让LEVEL先填不存在的字段。
- 当前pendulum/turntable/platform是单项，需支持多实例；三锤/升降分组及朝向必须变换主体、杆、锚点、速度和碰撞同一坐标系。复用现有运动/物理函数，保留旧配置兼容，勿整段替换成另一个物理实现或旧代码副本。
- 分支进度使用稳定节点/边/条件CP定义（可采用最小有向图），清楚区分路段检查标记与可重生CP。通过任一合法支路后能合流；其他支路CP不阻塞终点。落水保留本次已提交支路，重开清空，暂停不推进时间；乱序/跨支路跳过不可伪装合法完成。支路来源可在本关成绩里记录，当前总成绩按关卡/规则隔离，若记录字段扩展保持旧Run读取兼容。
- 显示进度依据实际当前路段和所选路径计算，不沿用全图线性Z进度；三路平均接近长度不能代替路径身份。共享资源实例化/取消/失败/卸载和大关卡性能预算必须明确，按需复用，无每个机关重复下载同一GLB。
- 静态模型与代理同源，移动/旋转件有真实碰撞，长窄跷跷/45°桥/杆身碰撞保持。设计中贴近端架/多个移动面连续接驳需要明确扫掠与接触窗口，不能用隐形承托、强绑球、传送或暗推球修“可玩性”。
- 第一期先提供单路线白盒及正式物理能力让LEVEL/ART并行配套；最终加入三路分支、静态精细模型、五项选关卡片/继续挑战/图鉴来源/纪录目录，完整接入两个新关，不停在白盒/协议。
- 保持当前.85球、基础质量/控制/摩擦/刹车/速度/重力/相机手感。若长关视线需优化优先调整场景遮挡和支撑，不默认改跟随镜头参数。商城/九球/七赛道、水色、纯净1200/600、性能同行与CI浮点修复不得回退。

## ART · 两条可复用赛道资源

按LEVEL冻结施工数据制作新 `art/top-difficulty.blend`、`art/three-route.blend` 及对应同名静态track GLB（建议top-difficulty-track.glb、three-route-track.glb）。这两个不同关卡允许各自初始源，后续原位维护，不建立v1/v2备份。共用现有机关库和单件移动模型；不将五种动态机关烘到静态路面，不为每个重复实例复制完整资源。

与CODE确认多朝向/多实例、端架是否需局部调整：必要新装配资产应共享、命名明确，不破坏旧三个关卡使用的库原点/尺寸/part路径。通过可复用路段/构件与材质语义制作，为未来官方Editor模板提供模块化基础；本轮不要求四套重复模型，也不新增完整编辑器。
