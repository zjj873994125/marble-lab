# 手机端：摇杆、刹车与精简横屏 HUD

用户明确要求手机适配，认为这项很重要，操作为“摇杆＋刹车＋横屏 HUD”，手机不需要大量提示模块。当前项目此前只有键盘输入，本任务需要真正可玩的触控输入，不能仅缩小桌面页面。

当前进展：CODE 已回传触控输入与横屏布局实际代码落盘，32项测试和构建通过；真实双指模拟、多尺寸画面与新难度下操作仍待验证，尚未整体验收。

最新外观反馈：用户先要求赛车手游踏板样式，随后在代码任务明确去掉外围按钮框和刹车文字，只留更小的踏板图标。当前以44×48的图标、透明无框无阴影外层、88px命中区为准；原浅底/外框/辅助文字建议已被替代，按住刹车行为保持。

## 范围与优先级

代码对话负责两关共用的触控输入和手机布局；关卡、美术继续第二关调难/S弯/独木桥配套，不因手机适配停工。第二关新几何未齐时，代码可先完成独立的触控工作；到位后合并验证触控与关卡，不把第一关其他独立美化再次设为前置。

保留 Vue3、Element Plus、Less 和 PlayCanvas，不新增 UI 框架或摇杆依赖。沿用现有品牌、色系和桌面键盘行为。用户已认可的物理、控制最大力度、摩擦、刹车衰减、质量、速度上限、镜头和成绩规则不改；手机只提供新的输入方式，不单独新增难度或成绩桶。

## 横屏布局

- 首页、选关、纪录、设置可在竖屏浏览；实际游戏以横屏为主。触控设备竖屏准备游戏时显示一句转横屏提示，避免在无法操作时计时/机关继续。游戏中旋回竖屏清空输入并暂停；回横屏保留进度，由用户明确继续，不突然自动运行。
- 不依赖强制横屏/全屏 API 才能使用。浏览器不支持或拒绝时正常展示手动旋转提示；不得通过 CSS 旋转整个页面产生触控方向错位。
- 顶部只保留紧凑计时、检查点进度和暂停按钮，可加很短关卡编号。长标题说明、WASD/方向键提示、页脚信息和独立掉落卡不在手机游戏中常驻；掉落和操作详情放暂停/结算中。
- 左下固定位置虚拟摇杆，右下大刹车键，均在双拇指自然区域。刹车按住持续生效、松开解除，清楚显示按下状态；暂停菜单保留重开、设置和返回，不让“重开”挤占主要触控区或容易误触。
- 中央和下方中央保持赛道视野；不重新铺满宽提示条或大白板。按钮点击区至少44px，摇杆/刹车使用明显更大的可控区域。适配刘海、圆角和底部安全区 env(safe-area-inset-*)，用动态视口高度应对浏览器地址栏。
- 手机横屏约740×360、844×390、932×430检查，竖屏约390×844检查旋转流程和菜单。不同尺寸不裁掉按钮、没有横向溢出；桌面/触屏笔记本输入不能仅凭窗口宽度误判，键盘仍可用。

## 输入契约与中断处理

- 摇杆提供连续二维方向和幅度，按屏幕方向与原键盘世界方向一致；有小死区、最大位移钳制，向量长度不超过1，避免斜向比直向快。满杆对应原最大控制输入，部分杆量可细调，灵敏度使用现有设置语义。
- 左手摇杆与右手刹车必须能同时按；各自按 pointerId 跟踪，松开一指不清掉另一指。移动端不把触摸映射成随机键盘按键或直接改实体位置；由明确的瞬时输入边界进入原力/刹车计算。
- Pointer Events 配合 pointer capture，拖出摇杆区域仍可控，抬手可靠归零。处理 pointerup、pointercancel、lostpointercapture、窗口失焦、切后台、旋屏、暂停/结算、重开、切关、组件卸载，不能留下持续移动或刹车。
- 对触控操作区设置合适 touch-action，防止游戏时页面滚动、长按选择和误触浏览器手势；菜单/设置内容正常可滚动。不要全站禁用页面交互。
- 输入状态仅保存在当前会话，不能写入设置/成绩或影响恢复存档。键盘与触摸合并时取明确优先级并限制总幅度，刹车可按两个来源的实际按下状态组合，不能叠加成双倍施力。
- Vue 只提供输入，不直接操纵 Ammo 实体；通过 GameCanvas 与运行时接口/hook 连接。复用当前关卡卸载/AbortController 流程，释放输入监听和捕获，不让上一关指针状态传到下一关。

必要测试覆盖输入向量范围/死区、独立双指、只松开一指、取消/失焦/切关清理、暂停不施力和恢复不继承残留；不写只镜像 CSS 的无效测试。运行统一 npm test、npm run build。

浏览器验证必须包括：横屏摇杆移动/转向；同时按刹车并继续持杆；松刹车后移动恢复；松杆归零；拖出区域后抬手；手势取消；切后台/暂停；横竖屏切换；重开/两关切换；入口与设置可触摸。正常手机尺寸下计时、检查点和暂停可读，控制区不挡住关键路径。

在第二关至少验证窄路方向细调和刹车等待机关，结合当前调难后的正式数据做移动端可操作性判断；不为了手机通过而暗改玩家摩擦或放大碰撞。桌面 WASD/方向键/空格/R/Esc 保持正常。

验证结果明确区分真实触控事件/模拟设备与真实手机。如果环境只有桌面模拟，交付模拟结果和待真机项，不宣称 iOS/Android 真机全部验收。使用本项目5177，不占用其他项目5173，不清除用户浏览器数据或改变其服务器配置。

交付放当前代码和现有 integration 说明/证据目录：横屏实画、竖屏提示/菜单、双指控制与松手/取消的记录，以及测试/构建结果。完成标准是手机能够实际操作两关且界面简洁，不能只交静态布局图。当前代码已落盘，完整触控与布局验收仍待完成。

代码阶段交接：新增 GameInput 瞬时接口经 App→GameCanvas→runtime 使用原施力12/灵敏度与刹车衰减；键盘方向优先，不叠加输入幅度。TouchControls 用独立pointerId支持摇杆和按住刹车，包含capture/释放/取消/失焦/旋屏/卸载清理；横屏简洁HUD、竖屏暂停提示和旋回需明确继续已实现。回传32项测试/构建通过，含4项向量、双指状态、清理、优先级有效测试；这些不能替代真正多指浏览器事件或真机结果。CODE 当前将手机与 challenge 新几何的最终验证合并，第一关/旧成绩保护继续。

## 刹车按钮外观修正：赛车手游踏板键

用户希望按键具有赛车游戏触控控件的观感。现实现是88×88浅色实心圆加大“刹车”文字，按下整块变橙；此次改为图形为主的踏板键，保持右下拇指位置与充分触控面积。

- 默认态：仅保留更小的踏板图形，当前SVG为44×48，外层背景透明、无边框/阴影，也不显示“刹车”文字；踏板自身少量防滑槽/孔可以保留。可访问名称保留，但不能作为可见辅助文字重新加回。
- 按住态：只在踏板图形内部点亮/轻微压下，不增加外围圈、按钮框或标签；不添加油门、漂移、氮气或压力进度条。松开/取消立即恢复，现有88px透明命中区不因图标变小而缩小。
- 延续本游戏橙色强调与克制半透明语言，避免换成与场景无关的竞品品牌图案。使用本地内联SVG/CSS原创简单图形即可，不需要截图裁切贴上或新增图片依赖；保持图标清楚，低画质也不依赖强模糊。
- 可见踏板的长宽比可以调整，但实际点击区不小于当前约88px尺度，至少满足44px触控规范；右侧/底部安全区不变，不挡住中央赛道。按钮按下动画只影响内部表现，外层捕获区域保持稳定，避免按住时移出点击区。
- 改动限于 TouchControls 当前模板/样式及必要资源清理，pointerId、capture、双指摇杆+刹车、松手/取消/旋屏/卸载清理与原刹车衰减保持。不新增按钮状态存储或修改关卡规则。
- 验证横屏740×360与844×390下默认/按住/松开三态及双指交互；给出正常游戏中的改后截图，不只独立放大图标。与手机整体和新难度验收合并，代码保持当前S弯物理试验与关卡交接，不为按键美化中断主流程。

CODE 已回传并落盘最新小图标默认/按住画面 `chrome-mobile-844-small-icon-default.png` / `pressed.png`，样式读数为border0、透明背景、无可见文字，触摸按住/松开正常。Chrome浏览器原生触控模拟还通过双指独立释放、保持摇杆时松刹车恢复加速、拖出抬手归零、touchCancel、按住时暂停，以及竖屏冻结计时/旋回待明确继续；证据 `mobile-controls-checks.json`。这是浏览器触控验证，不自动等同真实手机全机型验收；剩余尺寸、第一关触控和最终challenge全路线仍待CODE收口。
