日期：2026-09-11。状态：关卡/美术继续第二关，代码优先 GitHub 与项目 CI/CD 配置，服务器由用户部署。第二关建模明确沿用第一关风格，只增加新路线所需机关，不做独立水上主题包装。

最新路线修正：用户明确否定当前障碍一列排开的长条预览，要求在障碍物之间弯绕过渡。现有首份直线布局不再作为最终排布；由关卡在原设计文件中重排为紧凑的多次折返路线，美术依新布局原位调整当前 .blend，不改第一关、不建布局版本或备份。

最新机关结构修正：图中第二关大锤应使用跨赛道门架，两根方柱在行进方向左右两侧、横梁跨赛道，吊点在横梁中间且位于锤头中位正上方；默认静止姿态垂直居中，然后向两侧对称摆动。旧同侧支架/偏置吊点不作为最终方案，具体要求见文末。

## 目标与已确认边界

用户要求给建模和关卡设计分派工作，做另一个难度更高、障碍更多的关卡，可以参考《男生女生向前冲》，并补充三个核心方向：大转盘、相邻板块一上一下的升降路，以及需要加速和惯性才能通过的上坡。以这三个方向作为第二关核心，借鉴连续水上闯关、观察时机、失误落水、分段递进和冲线节奏，制作本项目自己的路线与造型。本轮未检索具体节目或声称复刻某期真实赛道。

第二关暂定中文名“水上冲关”，稳定关卡 ID/英文文件名 `water-rush`。最终目标是在本地关卡页可以选择并真实通关的独立第二关；首轮准备稿不是最终可玩交付。第一关保留，当前 UI、金属球滚动感和平端锤/短栏验收继续，不以新关卡替换或取消未完成事项。

- 以第一关当前模型为直接美术基准：同样的象牙台面、倒角、分层底座、支撑脚、固定件、橙色护栏和警示，已有水池环境继续复用。用户最新明确“建模还是和第一关一样，只是加障碍物”，不另做水上闯关主题外观、重新设计池体或用主题分区重配整关色彩。新转盘、升降板、坡道也应像同一套轨道零件。
- 沿用当前移动、刹车、镜头、弹珠直径/质量/摩擦/速度/重力；难度来自路线、机关数量和时机组合，不通过削弱操控或无提示隐形障碍增加难度。
- 现有实体没有跳跃能力，不能设计必须按跳跃键才能通过的关卡。转盘、Y 向升降、多实例相位及倾斜坡面均为本次新需求所需能力，由代码实现后才接入，不能把它们写成已支持，也不需要借此开发编辑器。
- 新关卡允许有自己的正式 `.blend`、GLB 和配置，这是独立内容，不是给第一关重复另存版本。新文件首次建立后直接维护同一份，不创建 v1/v2/candidate 副本或备份；不覆盖第一关文件，不删除历史资源。
- 当前入口保留用户设置的 127.0.0.1:5177；本地版本，无云端、账号、多人、关卡编辑器或排行榜扩展。

## 推荐体验与首版规模

首版按六段递进：一把现有平端锤、一座大转盘、四块交替升降板、一个横移平台和一段惯性坡，辅以短距离限宽/转弯。优先这组规模，不再以堆三把相同锤子作为主要难度。建议三处安全检查点承接转盘、升降路和冲坡前助跑区；实际位置由关卡验证。

1. **入口热身与单锤**：短距离错位通道接一把平端锤，保留观察和制动空间。用于从第一关过渡，不要求开局立即躲避连续机关。
2. **大转盘**：闭合圆形台面绕竖直轴旋转，图案或径向结构让旋转方向一眼可见。旋转必须真实影响站位或通过时机；可用一根与转盘同动的低挡杆增加绕行判断。若挡杆是可见障碍必须有匹配碰撞，不把假护栏或带缺口显示盖在整圆碰撞上。玩家可等时机登盘、控球离盘，不能只让贴图转。
3. **交替升降路**：首版四块相邻板，奇偶两组错相升降，呈一块上一块下。玩家在相邻台面高度接近时通过，并有可等待的固定岛；不需要主动跳跃键。板上弹珠的承托、升降接触与接缝必须真实验证，不用传送粘球或瞬移补通行。
4. **窄桥接横移缺口**：在控线后判断一个熟悉但更紧凑的横移窗口，复用现有平台机关。留缓冲落脚岛，不把升降末端直接接成没有观察空间的必死组合。
5. **助跑与惯性坡**：直线助跑区、平滑接入的上坡和完整坡顶落脚区。核心是“提前加速能冲上去、坡中从低速起步容易停住或滑回”，必须由原有力、重力、速度和真实斜坡碰撞自然产生，不设置隐藏速度门槛、自动弹射或人为拒绝通行。检查点放在足够助跑长度之前，不能复活在坡中。坡脚/坡顶无缝或窄倒角衔接，不留台阶卡球。
6. **坡顶收束冲线**：坡顶给制动与短距离控线空间，再进入清楚的终点；避免冲坡成功后必定因惯性撞出而失去成就感。

关卡需为三种新核心机关提供参数候选与依据：转盘直径/角速度/出口、升降高度范围/周期/相位/接驳窗口、坡角/高度/长度/助跑距离。坡度和高度要结合现有最大水平速度7、重力16及控制施力核算，但不能只用理想能量守恒推定真实摩擦和动力下的可通行性。建议熟悉后的整体通关目标约60–100秒，仅作设计长度目标；真实试玩前不定死奖牌。

## 当前能力缺口（已核对源码）

`LevelConfig` 当前只有一个 `pendulum`、一个 `platform`，无法通过复制数组项获得多机关。`runtime.ts`、`App.vue`、`state.ts` 直接引用 initial-gravity，Lobby/关卡入口文案也固定第一关。存档按规则版本分桶，尚不按关卡隔离，增加 TS 文件并不会自动成为可选第二关。

第二关所需代码能力为：独立关卡选择与完整卸载/加载；旋转盘及同动障碍、Y向升降平台多实例及独立相位、带真实倾角的坡面代理；按关卡加规则版本区分成绩；必要元数据和进度适配。先复用已有平端锤/横移平台资源与生命周期，限定新增能力服务上述三种核心体验，不扩展推板/翻板/浮力/跳跃或通用关卡编辑器。

## 路线修正任务：机关之间弯绕过渡

用户最新截图中，转盘之后的升降、窄桥、横移、助跑坡基本共用同一长轴，缺少行进方向变化。用户明确要求“不要这样一列排开，弯弯绕绕一下，比如在每个障碍物之间的过渡”。这属于本次已授权路线调整，不需要重复确认。

**关卡立即执行**：在现有 `water-rush.md` 和 `water-rush-layout.json` 中重排静态过渡、机关位置及检查点，保留六段体验与同款模型风格。

- 整体采用紧凑 S 形或 U 形折返布局，至少有三处明确的方向改变；不能仅把整条直线在场景里旋转后当作弯绕。
- 在单锤→转盘、转盘→升降、升降→横移、横移→冲坡之间安排短直道、L 形转弯或 U 形回转的组合，交替左右转向。过渡兼有减速、重新瞄准下一机关和短暂观察作用，避免全是装饰性长绕路。
- 四块升降板在自身挑战段内仍可直排，平台接驳局部结构优先保留已核对关系；通过整个机关段移位和段间连接实现路线变化，不随意破坏升降相位或改变核心挑战。
- 冲坡之前必须保留完整直线助跑长度，检查点位于助跑区之前。可以先转弯再进入助跑，不把急弯放在坡脚前而消除惯性冲坡机会。
